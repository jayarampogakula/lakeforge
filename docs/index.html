LakeForge Documentation

LakeForge is a unified, metadata-driven Medallion Lakehouse platform built for Apache Spark, Delta Lake, and Databricks Unity Catalog. Build, govern, validate, optimize, and deploy multi-tenant data pipelines using declarative JSON configurations.

🛡️ Unity Catalog RBAC 🔒 Fine-Grained PII Masking ⚡ Automated OPTIMIZE & VACUUM 🔄 Schema Drift & Evolution 🏢 Multi-Tenant Client Scoping 🚀 Azure DevOps & GitHub CI/CD

Enterprise Medallion Architecture

LakeForge decouples pipeline orchestration from ETL execution. Generic, parameterized Databricks notebooks read structured JSON metadata to dynamically ingest, clean, aggregate, govern, and maintain Delta tables across stages.

Bronze Ingestion

High-throughput ingestion with audit stamping (_ingestion_timestamp, _record_hash), file tracking, and configurable schema drift policies.

Silver Transformation

Declarative casting, standardization, deduplication, lookup joins, DDL schema enforcement, and SCD Type 2 history preservation.

Gold Marts & Views

Metric rollups, multi-table business aggregations, and decoupled on-demand Unity Catalog view creation.

Centralized Governance

Single configuration (access_control.json) enforcing RBAC grants, dynamic PII column masking, and row-level security across Unity Catalog.

Automated Maintenance

Automated OPTIMIZE, Z-ORDER co-location, VACUUM retention, and CBO ANALYZE TABLE statistics computation.

5-Minute Quickstart

Follow these steps to initialize your project, validate configurations, and deploy to your Databricks Lakehouse.

Terminal / Bash 
# Clone repository
git clone https://github.com/jayarampogakula/lakeforge.git
cd lakeforge

# Install core CLI and optional dev dependencies
pip install -e ".[dev]"
Terminal / Bash 
# Verify all JSON configuration schemas without requiring Spark
lakeforge validate --config-dir configs
Terminal / Bash 
# Deploy all assets (configs, notebooks, DABs) to the DEV stage
lakeforge deploy --stage dev

# Or deploy to production with dry-run verification
lakeforge deploy --stage prod --dry-run
Pro Tip: Zero-Spark Validation The LakeForge CLI uses standard Python libraries to parse and validate JSON metadata, allowing developers to run lightning-fast CI/CD gates on any standard runner without needing a Spark runtime.

Multi-Tenant Client Scoping

LakeForge supports unlimited enterprise customers or business units without duplicating pipeline code. Supply the client_id parameter when executing jobs or notebooks.

Config Directory Hierarchy & Fallback

When client_id="client_alpha" is provided, LakeForge first checks the client's dedicated folder. If a specific transformation or DQ rule is not defined there, it seamlessly falls back to global default configurations:

Directory Tree 
configs/
├── clients/
│   ├── client_alpha/              # Dedicated client tenant
│   │   ├── ingestion/             # Client-specific source overrides
│   │   ├── transformations/       # Client-specific Silver business logic
│   │   ├── aggregations/          # Client-specific Gold reporting marts
│   │   ├── views/                 # Client-specific View definitions
│   │   └── governance/            # Client-specific RBAC & catalog overrides
│   └── client_beta/
├── ingestion/                     # Global ingestion defaults
├── transformations/               # Global Silver transformations
├── aggregations/                  # Global Gold aggregations
└── governance/                    # Global Unity Catalog RBAC

Running a Client-Scoped Pipeline

Bash / CLI 
# Run Bronze ingestion for client_alpha
python -m lakeforge.cli.run_pipeline --layer bronze --name transactions --client client_alpha --env dev

# In Databricks Notebooks, simply set the 'client_id' widget:
# dbutils.widgets.text("client_id", "client_alpha")

Bronze Ingestion & Schema Evolution

The Bronze layer ingests raw files (CSV, JSON, Excel, Parquet, Avro, ORC) into Delta tables, automatically enriching every record with audit columns and tracking file-level lineage.

Schema Drift & Evolution Policies

Control how your pipeline handles incoming column drift using the schema_evolution property in your ingestion configuration:

Policy Behavior Use Case
allow (Default) Applies .option("mergeSchema", "true") to seamlessly adapt target Delta table to new incoming columns. Agile data lakes, rapid API changes, schema evolution.
strict Inspects existing target columns. If unexpected columns appear, it halts ingestion and raises SchemaDriftError. Financial ledgers, regulatory filings, strictly governed tables.
quarantine Routes records with drifted columns to <table>_quarantine while safely writing conforming columns to the main table. Zero-loss ingestion pipelines requiring immediate investigation.

Sample Ingestion Configuration

configs/ingestion/transactions.json 
{
  "source_name": "transactions",
  "source_type": "csv",
  "file_path": "/mnt/lake/landing/transactions/*.csv",
  "target_catalog": "lakeforge_dev",
  "target_schema": "bronze",
  "bronze_table": "transactions",
  "schema_evolution": "strict",
  "business_key": ["transaction_id"],
  "merge_strategy": "upsert",
  "options": {
    "header": "true",
    "inferSchema": "true",
    "delimiter": ","
  }
}

Data Quality Engine & Quarantine

Ensure zero bad data enters your analytics layers. LakeForge runs configurable assertions before writing to Bronze or Silver:

configs/dq/transactions.json 
{
  "rules": [
    {
      "rule_name": "pk_not_null",
      "rule_type": "null_check",
      "column": "transaction_id",
      "action": "fail",
      "severity": "critical"
    },
    {
      "rule_name": "positive_amount",
      "rule_type": "range_check",
      "column": "amount",
      "min_value": 0.01,
      "max_value": 1000000.0,
      "action": "quarantine"
    },
    {
      "rule_name": "valid_status",
      "rule_type": "allowed_values",
      "column": "status",
      "allowed_values": ["COMPLETED", "PENDING", "FAILED"],
      "action": "quarantine"
    }
  ]
}

Silver Cleansing, Transformations & SCD-2

Transform raw Bronze data into enterprise-grade cleansed models. LakeForge supports declarative transformations including explicit DDL schema casting:

configs/transformations/customers_clean.json 
{
  "target_table": "customers_clean",
  "schema": "customer_id INT, first_name STRING, last_name STRING, email STRING, phone STRING, region STRING, created_at TIMESTAMP",
  "transformations": [
    {
      "type": "standardize",
      "columns": ["first_name", "last_name"],
      "case": "title"
    },
    {
      "type": "standardize",
      "columns": ["email"],
      "case": "lower"
    },
    {
      "type": "filter",
      "condition": "email IS NOT NULL AND customer_id > 0"
    },
    {
      "type": "deduplicate",
      "key_columns": ["customer_id"],
      "order_by": "created_at",
      "order": "desc"
    }
  ]
}

Centralized Unity Catalog Governance & PII Masking

Manage all catalog grants, table permissions, fine-grained PII column masks, and row-level filters in a single central configuration file: configs/governance/access_control.json.

configs/governance/access_control.json 
{
  "roles": {
    "business_analysts": {
      "principals": ["analysts_group"],
      "catalogs": { "lakeforge_dev": ["USE CATALOG"] },
      "schemas": { "lakeforge_dev.silver": ["USE SCHEMA"] },
      "tables": { "lakeforge_dev.silver.customers_clean": ["SELECT"] }
    }
  },
  "masking_functions": [
    {
      "name": "mask_email",
      "schema": "silver",
      "input_column": "email",
      "expression": "CASE WHEN is_account_group_member('pii_admins') THEN email ELSE concat(substring(email, 1, 2), '****@****.com') END"
    }
  ],
  "column_masks": [
    {
      "table": "{catalog}.silver.customers_clean",
      "column": "email",
      "function": "{catalog}.silver.mask_email"
    }
  ],
  "row_filters": [
    {
      "name": "filter_by_region",
      "schema": "silver",
      "table": "{catalog}.silver.customers_clean",
      "filter_columns": ["region"],
      "expression": "is_account_group_member('global_data_access') OR region = current_user()"
    }
  ]
}

Automated Table Maintenance Suite

Prevent Delta file fragmentation and maintain query performance across Bronze, Silver, and Gold layers:

OPTIMIZE & Z-ORDER

Compacts small Parquet files into optimal 1GB files and co-locates rows by business keys for fast filter pushdowns.

VACUUM

Safely removes uncommitted files and snapshots older than retention threshold (default: 168 hours / 7 days).

ANALYZE TABLE

Computes statistics across key columns to allow the Spark Cost-Based Optimizer (CBO) to generate ideal join plans.

Maintenance CLI / Notebook 
# Run full maintenance across all Bronze, Silver, and Gold tables in DEV
python -m lakeforge.cli.run_pipeline --layer maintenance --env dev

# Or run the dedicated Databricks notebook:
# pipelines/MAINTENANCE_Table_Optimization.ipynb

CI/CD & Multi-Stage Deployment

LakeForge is CI/CD-agnostic. Use Azure DevOps or GitHub Actions with zero code changes.

azure-pipelines.yml 
trigger:
  branches:
    include: [main, release/*]

parameters:
  - name: stage
    displayName: "Stage"
    type: string
    default: dev
    values: [dev, test, staging, prod]

stages:
  - stage: BuildAndTest
    jobs:
      - job: TestJob
        steps:
          - script: pytest tests/unit_tests/ -v
          - script: lakeforge validate --config-dir configs

  - stage: DeployStage
    dependsOn: BuildAndTest
    jobs:
      - deployment: DeployJob
        steps:
          - script: lakeforge deploy --stage ${{ parameters.stage }}
.github/workflows/ci_cd.yml 
name: LakeForge CI/CD Multi-Stage Pipeline
on:
  push:
    branches: [main]
  workflow_dispatch:
    inputs:
      stage:
        type: choice
        options: [dev, test, staging, prod]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pytest tests/unit_tests/ -v
      - run: lakeforge validate --config-dir configs

  deploy:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - run: lakeforge deploy --stage ${{ inputs.stage || 'dev' }}

Observability, Run Ledger & Alerts

Every pipeline run records audit metrics (rows read, rows written, DQ violations, duration, status) into an append-only Delta audit ledger (lakehouse.monitoring.pipeline_run_ledger) and dispatches webhook alerts to Slack or Microsoft Teams upon failures.

Python Observability Example 
from lakeforge.observability.metrics import MetricsAuditor
from lakeforge.observability.alerts import AlertDispatcher

# Record run ledger entry
auditor = MetricsAuditor(spark=spark)
auditor.record_run(
    pipeline_name="transactions_bronze",
    stage="dev",
    status="SUCCESS",
    rows_read=150000,
    rows_written=149850,
    duration_seconds=42.5
)

# Dispatch alert on failure
dispatcher = AlertDispatcher(webhook_url="https://hooks.slack.com/services/...")
dispatcher.dispatch_alert(
    title="Data Quality Failure",
    message="150 records quarantined due to invalid transaction amounts.",
    severity="ERROR"
)
